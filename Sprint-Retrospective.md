# Sprint Retrospective

## Project Name

Piggy Bank Personal Finance Tracker

## What Went Well

During this sprint, our team worked on building the Piggy Bank website. We created a React and Vite project and added the main parts of the website, including expense categories, savings goals, money tips, and styling.

One thing that went well was that the website started to look complete and organized. We were able to add useful sections for users and make the project more professional with CSS and images.

I also learned more about using GitHub branches, commits, pull requests, and Vercel deployment. These tools helped me understand how real projects are shared and submitted.

## What Was Difficult

One difficult part was working with GitHub branches. Sometimes it was confusing to know which branch had the newest code. We also had a merge conflict in the README file when trying to merge the develop branch into main.

Another challenge was deployment. At first, I only had a localhost link, but that link only works on my own computer. I had to learn that Vercel is needed to create a public website link for submission.

## What I Contributed

I contributed to the frontend of the project. I worked on React components, styling, savings goals, expense categories, and preparing the website for deployment.

I also helped with GitHub work, including commits, pull requests, and merging changes so the project could be ready for submission.

## What We Can Improve Next Sprint

Next sprint, we should communicate more before editing the same files. This can help us avoid merge conflicts and confusion.

We should also make smaller pull requests instead of waiting until many changes are finished. Smaller pull requests are easier to review and merge.

We can also test deployment earlier in the sprint. This will give us more time to fix problems before the deadline.

## Proposed Solutions

For the next sprint, each team member should work on a separate branch for their own feature. We should also pull the latest changes before starting new work.

We should create pull requests more often and review them carefully before merging. This will help us catch problems earlier.

We should keep the README updated during the project instead of waiting until the end.

These solutions are realistic because they are simple steps our team can follow during the next sprint.

## Final Reflection

Overall, this sprint helped me learn more about React, CSS, GitHub, pull requests, merge conflicts, and deploying a website with Vercel.

I feel more comfortable working on a team project now. In the next sprint, I want to improve my GitHub workflow, communicate more with my team, and contribute more consistently.
